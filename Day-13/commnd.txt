  357  # Day-12 — Kubernetes Labels, Selectors & Namespaces
  358  ## Project Overview
  359  This project focused on understanding how Kubernetes organizes and manages resources using Labels, Selectors, and Namespaces.
  360  In real-world Kubernetes environments, hundreds of Pods, Services, and Deployments may run inside the same cluster. Labels and Namespaces help teams organize, identify, and isolate resources efficiently.
  361  ---
  362  # Technologies Used
  363  * Kubernetes
  364  * kubeadm Cluster
  365  * kubectl
  366  * Docker
  367  * AWS EC2
  368  * Ubuntu Linux
  369  ---
  370  # Concepts Covered
  371  ## Labels
  372  Labels are key-value pairs attached to Kubernetes objects.
  373  Example:
  374  ```yaml
  375  labels:
  376    app: flask
  377    env: dev
  378    team: backend
  379  ```
  380  Labels help identify and group resources.
  381  ### Real-World Use Case
  382  A company may have:
  383  ```text
  384  Frontend Pods
  385  Backend Pods
  386  Database Pods
  387  ```
  388  Labels help distinguish them:
  389  ```text
  390  app=frontend
  391  app=backend
  392  app=database
  393  ```
  394  ---
  395  ## Selectors
  396  Selectors use labels to find Kubernetes resources.
  397  Example:
  398  ```yaml
  399  selector:
  400    app: flask
  401  ```
  402  Meaning:
  403  ```text
  404  Find all Pods where app=flask
  405  ```
  406  ### Real-World Use Case
  407  Services use selectors to discover Pods and distribute traffic.
  408  ```text
  409  Service
  410     ↓
  411  Selector
  412     ↓
  413  Matching Pods
  414  ```
  415  ---
  416  ## Namespaces
  417  Namespaces logically divide a Kubernetes cluster into separate environments.
  418  Example:
  419  ```text
  420  Cluster
  421  │
  422  ├── default
  423  ├── frontend
  424  ├── backend
  425  └── production
  426  ```
  427  ### Real-World Use Case
  428  Different teams can share the same cluster without resource conflicts.
  429  ```text
  430  Frontend Team
  431  Backend Team
  432  DevOps Team
  433  ```
  434  Each team can work in its own namespace.
  435  ---

  595  # Problems Faced During the Project
  596  ## 1. Resources Not Visible
  597  ### Problem
  598  Pods were not visible when running:
  599  ```bash
  600  kubectl get pods
  601  ```
  602  ### Root Cause
  603  Pods were deployed in a different namespace.
  604  ### Resolution
  605  Specified namespace:
  606  ```bash
  607  kubectl get pods -n frontend
  608  kubectl get pods -n backend
  609  ```
  610  ### Learning
  611  Kubernetes resources are isolated by namespaces.
  612  ---
  613  ## 2. Service Unable to Discover Pods
  614  ### Problem
  615  Service showed no endpoints.
  616  ### Root Cause
  617  Service selector labels did not match Pod labels.
  618  Example:
  619  ```yaml
  620  selector:
  621    app: frontend
  622  ```
  623  Pod:
  624  ```yaml
  625  labels:
  626    app: nginx
  627  ```
  628  ### Resolution
  629  Updated labels to match the Service selector.
  630  ### Learning
  631  Selectors must match Pod labels exactly.
  632  ---
  633  # Key Learnings
  634  * Labels identify Kubernetes resources.
  635  * Selectors find resources using labels.
  636  * Services use selectors to discover Pods.
  637  * Namespaces isolate workloads.
  638  * Multiple teams can share the same cluster safely.
  639  * Namespace context can be changed using kubectl.
  640  * Labels are heavily used in production environments.

  642  # Interview Questions
  643  ### What are Labels?
  644  Labels are key-value metadata attached to Kubernetes resources for identification and grouping.
  645  ### What are Selectors?
  646  Selectors use labels to locate Kubernetes resources.
  647  ### Why do Services use Selectors?
  648  Services use selectors to discover matching Pods and route traffic.
  649  ### What are Namespaces?
  650  Namespaces logically separate resources inside a Kubernetes cluster.
  651  ### Can two namespaces contain deployments with the same name?
  652  Yes. Namespaces provide isolation, allowing resources with the same name to exist in different namespaces.
